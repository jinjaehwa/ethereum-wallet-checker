# Ethereum Wallet Checker

Ethereum JSON-RPC를 이용해 지갑 주소의 ETH 잔액과 현재 블록 번호를 조회하는 웹페이지입니다.

HTML, CSS, JavaScript를 사용했으며, 별도의 백엔드 서버나 외부 라이브러리 없이 브라우저에서 동작하도록 제작했습니다.

이번 프로젝트는 ChatGPT를 전적으로 활용하여 개발했습니다. 아직 프로그래밍에 대한 기초 지식이 부족하기 때문에 AI의 도움으로 코드를 작성하고, 실제로 실행하면서 기능을 확인하고 이해하는 방식으로 진행했습니다.

## 1. 주요 기능

- **ETH 잔액 조회:** 입력한 이더리움 지갑 주소의 잔액을 ETH 단위로 표시합니다.
- **블록 번호 조회:** 현재 이더리움 네트워크의 최신 블록 번호를 표시합니다.
- **주소 형식 검사:** `0x`로 시작하는 40자리 16진수 주소인지 검사합니다.
- **로딩 상태 표시:** 조회 중에는 버튼을 비활성화하여 중복 요청을 방지합니다.
- **오류 처리:** 잘못된 주소, 네트워크 연결 실패, 서버 응답 오류 등을 안내합니다.
- **Enter 키 조회:** 조회 버튼을 클릭하지 않아도 Enter 키로 조회할 수 있습니다.

## 2. 실행 방법

1. GitHub 저장소를 다운로드하거나 복제합니다.
2. 프로젝트 폴더의 `index.html` 파일을 브라우저에서 실행합니다.
3. 지갑 주소를 입력하고 조회 버튼을 클릭하거나 Enter 키를 누릅니다.
4. ETH 잔액과 현재 블록 번호를 확인합니다.

테스트에 사용한 지갑 주소:

`0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045`

별도의 설치 과정이나 API 키는 필요하지 않지만, RPC 서버와 통신하기 위해 인터넷 연결이 필요합니다.

## 4. 데이터 조회 및 처리 방식

Ethereum JSON-RPC를 이용하며, 다음 두 메서드를 사용했습니다.

**`eth_getBalance`**

지정한 지갑 주소의 잔액을 조회하는 메서드입니다. 반환값은 Wei 단위의 16진수입니다.

**`eth_blockNumber`**

가장 최근 블록의 번호를 조회하는 메서드입니다. 반환값은 16진수입니다.

두 메서드의 의미를 이해하기 위해 Ethereum 공식 JSON-RPC 문서를 직접 찾아봤습니다.

RPC 엔드포인트:

`https://ethereum-rpc.publicnode.com`

JavaScript의 `fetch()`를 사용하여 RPC 서버에 POST 요청을 보냅니다.

서버에서 반환된 값은 그대로 표시하기 어려워 변환 과정이 필요했습니다.

- ETH 잔액은 1 ETH = 10¹⁸ Wei를 기준으로 변환합니다.
- `BigInt`를 사용하여 큰 정수를 정확하게 계산합니다.
- ETH 잔액은 정수 부분과 소수 부분을 나누어 표시합니다.
- 블록 번호는 16진수에서 10진수로 변환합니다.

AI가 일반적인 숫자 처리 대신 `BigInt`를 사용한 이유도 궁금했습니다. 큰 정수를 일반적인 JavaScript 숫자로 처리하면 정확도가 떨어질 수 있기 때문이라는 것을 알게 되었고, 1 ETH와 1 Wei 등의 값을 테스트하여 변환 결과를 확인했습니다.

## 5. 추가 기능 및 개선 사항

### 추가 기능: Enter 키로 조회

기존에는 지갑 주소를 입력한 후 조회 버튼을 클릭해야 했습니다.

이를 개선하기 위해 Enter 키만으로도 조회할 수 있는 기능을 추가했습니다. 사용자가 마우스를 사용하지 않아도 바로 조회할 수 있어 편리하다고 판단했습니다.

기존 조회 버튼의 동작을 재사용했으며, 조회 중에는 Enter 키를 반복해서 눌러도 중복 요청이 발생하지 않도록 처리했습니다.

### 코드 개선: RPC 병렬 요청

초기 코드에서는 ETH 잔액을 조회한 후 블록 번호를 조회하는 순차 처리 방식을 사용했습니다.

이후 AI가 제안한 `Promise.all()`을 적용하여 서로 독립적인 두 요청을 동시에 실행하도록 변경했습니다.

개선된 코드가 정상적으로 동작하는지 확인하기 위해 Chrome 개발자 도구의 Network 탭을 사용했습니다. 두 RPC 요청이 정상적으로 완료되고 실행 시간이 겹치는 것을 직접 확인했습니다.

프로젝트를 진행하면서 다음 기능을 테스트했습니다.

| 빈 주소 입력 시 안내 메시지 | 성공 |
| 잘못된 주소 입력 시 오류 표시 | 성공 |
| 이전 조회 결과 초기화 | 성공 |
| 조회 중 로딩 상태 표시 | 성공 |
| 네트워크 연결 실패 처리 | 성공 |
| 병렬 RPC 요청 동작 | 성공 |
| Enter 키 조회 | 성공 |

테스트 과정에서 몇 가지 문제가 있었습니다.

**GitHub 저장소 연결 문제**

처음에는 원격 저장소 주소를 설정하면서 예시로 제공된 `본인아이디` 부분을 실제 계정명으로 바꾸지 않았습니다. 이후 원격 저장소가 이미 존재한다는 오류가 발생했고, AI의 안내에 따라 `git remote set-url origin` 명령어로 주소를 수정했습니다.

**CSS 코드 누락**

로딩 중 버튼의 색상과 커서 모양을 변경하는 CSS 코드를 추가하지 않은 상태로 커밋한 사실을 뒤늦게 발견했습니다. 누락된 코드를 추가한 뒤 별도로 커밋했습니다.

**네트워크 오류 테스트**

처음에는 브라우저를 오프라인 상태로 설정한 뒤 잘못된 주소인 `abc123`을 입력했지만 네트워크 오류가 발생하지 않았습니다.

이후 주소 형식 검사가 먼저 실행되어 RPC 요청까지 진행되지 않았다는 것을 알게 되었습니다. 정상적인 지갑 주소로 다시 테스트한 결과 네트워크 오류 메시지가 표시되는 것을 확인했습니다.

## 7. 구현하지 않은 기능

**거래 내역 조회**

이번 과제의 필수 기능인 ETH 잔액과 블록 번호 조회에 집중하기 위해 제외했습니다.

**MetaMask 연동 및 거래 전송**

이번 프로젝트는 지갑 정보를 확인하는 읽기 전용 프로그램이므로 구현하지 않았습니다.

**EIP-55 체크섬 검증**

현재는 정규표현식을 이용하여 주소의 기본적인 형식만 검사합니다. 주소의 대소문자를 활용하는 체크섬 검증은 구현하지 않았습니다.

## 8. AI 활용 및 개발 과정

이번 프로젝트는 **ChatGPT를 전적으로 활용하여 제작했습니다.**

프로젝트의 기본 구조부터 HTML, CSS, JavaScript 코드 작성, 오류 처리, 기능 추가, 코드 개선까지 대부분의 코드를 AI가 작성했습니다. 저는 AI가 제안한 코드를 적용하고, 브라우저에서 실행해 보면서 정상적으로 작동하는지 확인하는 방식으로 진행했습니다.

다만 코드를 단순히 적용하는 데 그치지 않고, 이해되지 않는 부분에 대해서는 이유를 확인하려고 했습니다.

처음에는 HTML, CSS, JavaScript 파일을 분리하는 이유가 궁금했고, RPC 연결 과정에서는 `eth_getBalance`와 `eth_blockNumber`가 무엇인지 알아보기 위해 공식 문서를 찾아봤습니다. 데이터 변환 과정에서는 `BigInt`를 사용하는 이유를 확인했고, 오류 처리 과정에서는 주소 검증과 네트워크 요청이 어떤 순서로 실행되는지도 알게 되었습니다.

또한 AI가 제안한 코드가 실제로 작동하는지 직접 테스트했습니다. 특히 RPC 병렬 처리 방식은 개발자 도구에서 요청 시간을 확인했고, 코드나 설정을 누락하여 문제가 발생했을 때는 원인을 확인한 후 수정했습니다.

GitHub 커밋 메시지도 처음에는 한국어로 작성하고 싶었지만, 일반적으로 사용되는 영어 커밋 형식을 참고하여 작성했습니다.

현재는 AI의 도움 없이 전체 코드를 독립적으로 작성하거나 모든 동작을 설명할 수 있는 수준은 아닙니다. 특히 JavaScript의 비동기 처리, `Promise.all()`, `BigInt`, JSON-RPC의 구체적인 동작 원리 등은 추가적인 학습이 필요합니다.

이번 프로젝트를 통해 AI를 활용하면 프로그램을 빠르게 구현할 수 있지만, **코드가 실제로 어떻게 동작하는지 이해하고 검증하는 과정도 중요하다**는 것을 느꼈습니다. 앞으로는 완성된 코드를 다시 분석하고 직접 구현해 보면서 부족한 기초 지식을 보완하고자 합니다.
